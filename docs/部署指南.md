# Recall AI 错题本：免费部署指南（EdgeOne Makers）

> 主方案：**EdgeOne Makers（腾讯云，免费版永久提供，国内访问快）+ Supabase（免费云数据库）**。全程不需要信用卡，**永久免费**，适合课程作业演示。
>
> EdgeOne Makers（原 EdgeOne Pages）已支持 Next.js **全栈**应用（SSR + API 接口，官方模板即 Next.js 15），本项目可以直接部署，不需要改动代码。
>
> 备用方案（同为腾讯云）：[CloudBase 云托管](./CloudBase部署指南.md)（免费体验版需每半年手动续费）。

代码已经内置 Supabase 云端持久化：部署后新增/修改的错题会保存到云端，不会因为服务器重启而丢失。不配置 Supabase 时仍会在本地使用 `data/recall-db.json`，方便开发。

## 整体架构

```
用户浏览器 ──▶ EdgeOne Makers（跑 Next.js 全栈，含 /api 接口）
                    │
                    └──▶ Supabase 云数据库（存错题/账号，区域选 Singapore/Tokyo）
```

## 准备

- GitHub 账号（仓库已经推到 GitHub）
- Supabase 账号（邮箱注册即可）
- 腾讯云账号（EdgeOne Makers 登录后开通免费版即可，无需信用卡）
- 本地 `recall-app/.env.local` 里的 DeepSeek / OCR.space 密钥（部署时要复制到 EdgeOne）

## 1. 创建 Supabase 项目

1. 打开 [supabase.com](https://supabase.com)，注册并登录。
2. 点 **New project**。
3. 项目名称随意，例如 `recall-ai`；设置数据库密码并记下来；Region 建议选 **Singapore（东南亚）** 或 **Tokyo（日本）**，国内访问相对快。
4. 等几分钟让项目创建完成。

## 2. 创建云端数据表

1. 左侧菜单进入 **SQL Editor**。
2. 新建查询，粘贴仓库中 `supabase/schema.sql` 的内容。
3. 点 **Run**，看到成功提示即可。这会创建一张 `app_state` 表，用来保存整个错题本数据。

## 3. 关闭邮箱确认

默认情况下 Supabase 注册后会要求先点邮件确认链接，课程演示会很麻烦。

1. 左侧菜单进入 **Authentication** -> **Sign In / Providers**。
2. 找到 **Email**，点 **Edit**。
3. 取消勾选 **Confirm email**，保存。

## 4. 创建演示账号

让登录页的“使用演示账号进入”按钮可以直接使用：

1. 进入 **Authentication** -> **Users** -> **Add user**。
2. Email 填 `demo@recall.app`，密码填 `recall123`。
3. 确保 **Auto Confirm User** 开启（不同版本界面可能叫法不同）。
4. 点 **Add user**。

## 5. 获取 Supabase 密钥

1. 左侧菜单进入 **Project Settings** -> **API**。
2. 复制三个值：**Project URL**、**anon public**、**service_role**。
3. `service_role` 是敏感密钥，只能填到 EdgeOne 服务端环境变量里，不要贴到公开代码或网页中。

## 6. 部署到 EdgeOne Makers

1. 打开 [EdgeOne Makers 控制台](https://edgeone.ai/zh/products/pages)（腾讯云，登录后按提示**开通免费版**，免费版永久提供）。
2. 点 **新建项目** → 选 **导入 Git 仓库** → 授权 GitHub（也支持 GitLab / Bitbucket）。
3. 选中 `recall-ai-wrong-book` 仓库；**Root Directory（根目录）** 填 `recall-app`（项目在仓库子目录里）。
4. **框架预设选 Next.js**，构建命令 `npm run build`，输出目录 `.next/`，保持默认即可。
5. 在 **环境变量** 区域添加以下变量（变量名必须和本地 `.env` 完全一致）：

   | 变量名 | 值来源 |
   | --- | --- |
   | `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon public |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabase service_role |
   | `DEEPSEEK_API_KEY` | 本地 `.env.local` |
   | `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` |
   | `DEEPSEEK_MODEL` | `deepseek-chat` |
   | `OCR_SPACE_API_KEY` | 本地 `.env.local` |

   > 说明：`NEXT_PUBLIC_` 开头的变量在构建时会打包进前端代码，其余变量只在服务端使用。`hasSupabaseEnv()` 要求 `NEXT_PUBLIC_SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY` 都非空才启用云数据库，否则会退回本地临时文件、数据不持久，所以这几个务必都填。

6. 点 **部署**，约 30 秒到 2 分钟构建完成，得到 `https://xxx.edgeone.cool` 访问域名。
7. （可选）绑定自己的域名：项目设置 → **域名管理** → 添加自定义域名，按提示在 DNS 服务商加一条 CNAME 记录即可。

> 之后每次 `git push`，EdgeOne 会自动触发重新部署，无需手动操作。

## 7. 验收

打开 EdgeOne 分配的 `https://xxx.edgeone.cool`：
1. **有颜色、有居中布局** —— 样式正常。
2. 点“使用演示账号进入” → 能进首页 —— 登录接口正常。
3. 录一道错题，刷新页面数据还在 —— Supabase 生效。
4. 换一个浏览器注册新账号 → 能登录。
5. 新增/修改数据后刷新页面，数据仍然在，说明云端持久化已生效。

## 常见问题

- **打开页面 500 或 API 报错**：检查 Supabase SQL Editor 是否执行过 `schema.sql`，以及环境变量是否填写正确（尤其 `NEXT_PUBLIC_SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY` 两个）。
- **登录提示邮箱未确认**：检查 Supabase Authentication 里是否关闭了 Confirm email，或演示账号是否开启了 Auto Confirm。
- **刷新后数据丢失**：确认 `SUPABASE_SERVICE_ROLE_KEY` 已配置。线上必须配置 Supabase；不配置时仍使用本地 JSON，但 EdgeOne 临时磁盘不会保留数据。
- **`next.config.mjs` 里的 `output: "standalone"` 要改吗？** 不用。那是给 CloudBase 云托管准备的，对 EdgeOne 的构建和运行没有影响，本地 `npm run dev` 也不受影响。
- **构建失败**：查看部署日志（Build Logs / Build Summary）排查，常见是环境变量漏填导致 `NEXT_PUBLIC_*` 为空。
- **Supabase 免费项目连续 7 天无活动会暂停**：演示前登录一下 Supabase Dashboard 即可自动恢复。
