## 一、当前登录方式（现状）

| 环节 | 实现方式 |
|---|---|
| 注册 | 昵称 + 邮箱 + 密码 → `/api/auth/register` → Supabase `signUp` → 自动发确认邮件 |
| 注册确认 | 注册成功 → 邮箱收到 **6 位验证码** → 回到注册页填码 → 应用内完成验证并登录（不依赖点链接） |
| 登录 | 邮箱 + 密码 → `/api/auth/login` → `signInWithPassword` → 写登录 cookie |
| 验证码登录 | 登录页「验证码登录」→ 输入邮箱发 **6 位验证码** → 填码登录（免密码） |
| 忘记密码 | 登录页「忘记密码」→ 发重置邮件 → `/reset-password` 页面设新密码 |
| 登录态 | cookie `recall_session=supabase:<token>`，有效期 7 天，`Secure` + `HttpOnly` + `SameSite=lax` |
| 发信服务 | 自定义 SMTP = QQ 邮箱（`smtp.qq.com:465`，发件人 `2017617345@qq.com`） |
| 登录保护 | `middleware.ts`：未登录访问 → 跳 `/login`；http 请求 → 强制 308 跳 https |
| 演示账号 | `demo@recall.app` / `recall123`（登录页一键进入） |

## 二、已经修复的问题（历史踩坑记录）

> 已修复，记录在此避免重复踩坑。

1. **手机 http 打开登录闪回登录页**
   - 根因：cookie 带 `Secure`，手机走 http 时浏览器拒绝保存。
   - 修复：`middleware.ts` 顶部按 `x-forwarded-proto` 判断，http 一律 308 跳 https。
   - 坑：URL 对象 `host` 只读须字符串拼接；`Host` 头带容器端口 `:3000` 须 `split(":")[0]` 剥离。

2. **Supabase 环境变量不生效（NEXT_PUBLIC_ 前缀坑）**
   - 根因：`NEXT_PUBLIC_` 前缀变量在 Docker 构建时被内联进代码，构建时为空则运行时注入环境变量也读不到。
   - 症状：DeepSeek（非前缀）生效、Supabase（前缀）不生效。
   - 修复：`lib/supabase.ts` 改读非前缀 `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`（兼容旧前缀），`Dockerfile` 删除对应 `ARG/ENV`。

3. **内置邮件限流（2 封/小时）**
   - 根因：Supabase 内置邮件服务每小时最多发 2 封，短时间注册即触发 `email rate limit exceeded`。
   - 修复：配置 QQ 邮箱自定义 SMTP，绕过内置限制。

4. **切换数据库后旧 cookie 失效**
   - 现象：换项目后浏览器残留旧登录记录，打开 app 直接进首页但提示「加载错题失败」。
   - 原因：middleware 只看 cookie 前缀放行，API 校验 token 失败返回 401。
   - 处理：用户清除网站 cookie / 用无痕窗口重新登录。

## 三、本次上线的新功能（2026-08-19）

### 1. 登录报错中文化 ✅
- `/api/auth/login` 把 Supabase 错误映射成中文：
  - 凭证错误 →「邮箱或密码错误」
  - 邮箱未确认 →「请先到邮箱确认后再登录」
  - 其余 →「登录失败，请稍后重试」

### 2. 忘记密码 ✅
- 登录页 →「忘记密码」→ 输入邮箱 → 发重置邮件。
- 邮件链接指向 `/reset-password` 页面，填新密码完成修改。
- 后端：`/api/auth/forgot-password`（发邮件）+ `/api/auth/reset-password`（用 recovery token 改密码）。
- ⚠️ 依赖第四节第 1 步：Site URL 必须是正式网址，否则邮件里的链接指向 localhost 打不开。

### 3. 邮箱验证码登录 + 注册应用内确认 ✅
- 登录页「验证码登录」→ 输邮箱 → 收到 6 位验证码 → 填码登录（免密码）。
- 注册成功后在**同一页**填验证码完成邮箱确认并登录（不用点链接了）。
- 后端：`/api/auth/otp/send`（发码）+ `/api/auth/otp/verify`（校验并写登录 cookie）。
- ⚠️ 依赖第四节第 2 步：邮件模板里必须加 `{{ .Token }}`，否则邮件只有链接、没有 6 位验证码，这个功能就用不了。

## 四、⚠️ 部署后必做：Supabase 控制台手动配置（傻瓜式步骤）

> 这两步**在控制台操作，不用写代码**。做完后三件事才能完全正常：
> 1. 确认邮件 / 重置邮件里的链接不再是 `localhost:3000`；
> 2. 邮件里能看到 6 位验证码，验证码登录和注册填码确认才能用。

### 第 1 步：改「网站地址」（Site URL）

1. 浏览器打开 Supabase 控制台：`https://supabase.com/dashboard/project/arknxiefxxlxvrtyvxrb`，登录你的 GitHub 账号。
2. 左侧菜单点 **Authentication（认证）** → 点顶部的 **URL Configuration（网址配置）**。
3. 找到 **Site URL** 输入框，把里面的 `http://localhost:3000` **全部删掉**，改成：

   ```
   https://recall-wrong-298783-11-1350512420.sh.run.tcloudbase.com
   ```

4. 往下找到 **Redirect URLs**，点 **Add URL**，填：

   ```
   https://recall-wrong-298783-11-1350512420.sh.run.tcloudbase.com/**
   ```

5. 点 **Save**（保存）。✅

### 第 2 步：让邮件显示 6 位验证码（改两个邮件模板）

Supabase 默认邮件只有「点按钮确认」的链接，没有验证码。要加两处：

1. 左侧菜单 **Authentication（认证）** → 点顶部的 **Emails（邮件）** 标签 → 点 **Templates（模板）**。
2. 找到 **Confirm signup**（注册确认）那一行，点右侧 **Edit**（编辑）。
3. 在 **Subject**（邮件标题）里改成：

   ```
   确认你的 Recall 账号，验证码：{{ .Token }}
   ```

   在 **Body**（邮件正文）里，把文字改成（可保留原来的按钮链接，也可删掉）：

   ```
   <h2>确认你的 Recall 账号</h2>
   <p>你的 6 位验证码是：</p>
   <p style="font-size:24px;font-weight:bold;letter-spacing:4px">{{ .Token }}</p>
   <p>回 app 注册页，把这 6 位填进去完成验证。</p>
   <p>（也可以点这个链接直接确认）</p>
   ```

   点 **Save**。
4. 找到 **Magic Link**（魔法链接）那一行，同样点 **Edit**，Subject / Body 里加 `{{ .Token }}`（这就是「验证码登录」用的邮件模板），保存。
5. 两个都保存完就 OK 了 ✅

> 提示：`{{ .Token }}` 是占位符，发信时 Supabase 会自动替换成该用户真实的 6 位验证码。

### 如何验证是否配好

用一个新的 QQ 邮箱注册，检查收到的确认邮件：
- 链接地址是 `recall-wrong-298783-11-...tcloudbase.com` 而不是 `localhost:3000` ✅
- 邮件里有一个 **6 位数字验证码** ✅

## 五、傻瓜式操作指南（给使用者）

### 注册 + 验证（新流程，不用点链接了）
1. 打开 app 网址 → 点「注册」→ 填昵称、**真实邮箱**、密码（≥6 位）→ 点「注册」。
2. 页面变成「验证码」输入框。打开邮箱（**注意看垃圾箱 / 广告邮件**），找发件人是你的 QQ 邮箱的邮件，复制里面的 **6 位数字验证码**。
3. 把验证码填进 app 的输入框 → 点「验证并登录」→ 进入主页。

### 验证码登录（免密码）
1. 登录页点「验证码登录」→ 输邮箱 → 点「发送验证码」。
2. 去邮箱复制 6 位验证码 → 填回来 → 点「验证并登录」。

### 忘记密码
1. 登录页点「忘记密码」→ 输注册邮箱 → 点「发送重置邮件」。
2. 去邮箱点邮件里的链接（会打开一个「重置密码」页面）。
3. 输入新密码（≥6 位）→ 点「确认修改」→ 提示成功后回登录页用新密码登录。

### 密码登录
- 填邮箱 + 密码 → 点「登录」。
- ⚠️ 密码注意大小写，首字母大写，中间无空格。
- 密码忘了就用上面的「忘记密码」自己找回，不用找管理员了。

### 常见问题
| 现象 | 原因 | 怎么办 |
|---|---|---|
| 收不到验证码/确认邮件 | 邮箱填错 / 在垃圾箱 / 超 1 小时发信限制 | 看垃圾箱；等一会儿再试；换真实邮箱 |
| 邮件里没有 6 位验证码 | 模板没加 `{{ .Token }}` | 做第四节第 2 步 |
| 确认/重置链接打不开（localhost） | Site URL 还是 localhost | 做第四节第 1 步 |
| 验证码登录提示验证码错误 | 输错 / 已过期（几分钟内有效） | 重新点「发送验证码」 |
| 提示「邮箱或密码错误」 | 邮箱或密码输错 | 核对大小写与空格；忘记密码就点「忘记密码」 |
| 打开 app 直接进首页但提示加载失败 | 浏览器残留旧登录记录 | 清除网站 cookie，或换无痕窗口重登 |
